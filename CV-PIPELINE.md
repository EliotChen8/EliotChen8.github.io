# CV pipeline — handoff for the site maintainer

This document is self-contained. It describes how the CV on
`https://eliotchen8.github.io/cv/` goes from one LaTeX file to a rendered web
page and a downloadable PDF, what each file does, the invariants you must keep,
and how to install, verify and extend the pipeline.

Site: Jekyll + AcademicPages (a Minimal Mistakes fork), repo
`EliotChen8/EliotChen8.github.io`, default branch **`main`**.

---

## 1. One-paragraph summary

The owner edits the CV in Overleaf, copies the finished `main.tex` by hand into
`_cv/main.tex`, commits and pushes. A local pre-commit hook first refuses the
commit if the file contains any private term. On push, one GitHub Actions
workflow (a) compiles `main.tex` to PDF with TeX Live, (b) converts the same
`main.tex` to an HTML fragment with a small purpose-built Python converter,
(c) builds the Jekyll site, which embeds that fragment into `/cv/`, and
(d) deploys to GitHub Pages. No credentials or secrets are involved anywhere.

```
Overleaf (private, master copy, keeps everything)
   │  manual copy of main.tex only
   ▼
_cv/main.tex ──git commit──► [.githooks/pre-commit: blocklist scan] ──push──►
   GitHub Actions (build-site.yml)
     ├─ latexmk (xu-cheng/latex-action)   _cv/main.tex → _cv/main.pdf → files/TianyangChen_CV.pdf
     ├─ python3 _cv/tex2html.py           _cv/main.tex → _includes/cv-body.html
     ├─ jekyll build (jekyll-build-pages) _pages/cv.html + includes → _site/cv/index.html
     └─ deploy-pages                      _site → https://eliotchen8.github.io
```

## 2. Files and their roles

| Path | Committed? | Role |
|---|---|---|
| `_cv/main.tex` | yes | **Single source of truth** for both outputs. Underscore dir, so Jekyll never publishes it as a page (but the repo is public, so the file itself is readable on GitHub). |
| `_cv/tex2html.py` | yes | LaTeX → HTML fragment converter (stdlib only, Python ≥ 3.8). |
| `_includes/cv-style.html` | yes | `<style>` block, all rules scoped under `.cv-tex`. Inherits site font and colors. |
| `_pages/cv.html` | yes | The `/cv/` page. Front matter + download link + includes. **Must stay `.html`, not `.md`** (see §5). |
| `.github/workflows/build-site.yml` | yes | Build + deploy workflow. |
| `.githooks/pre-commit` | yes | Local guard; only active after `git config core.hooksPath .githooks`. |
| `_includes/cv-body.html` | **no** (gitignored) | Generated by step 2 of the workflow. |
| `files/TianyangChen_CV.pdf` | **no** (gitignored) | Generated by step 1 of the workflow. |
| `.cv-blocklist` | **no** (gitignored, local only) | Private terms, one per line. Never commit it: its contents are themselves private. |

## 3. What happens, step by step

### Step 0 — Local commit guard (`.githooks/pre-commit`, on the owner's machine)

1. Exits 0 immediately if `.cv-blocklist` does not exist, or if `_cv/main.tex`
   is not among the staged files.
2. Writes the **staged** blob (`git show :_cv/main.tex`) to a temp file, so it
   checks exactly what would be committed, not the working copy.
3. Runs `python3 _cv/tex2html.py <tmp> --check --blocklist .cv-blocklist`.
   - Case-insensitive substring match of every blocklist term against every
     line of the **raw** source, comments included.
   - Any hit → prints `BLOCKED: line N: contains blocklisted term '…'` and exits 1,
     so git aborts the commit.
   - Then performs a full dry-run conversion, so an unsupported macro is also
     caught before commit.

Why local and not in CI: CI runs after `git push`, when the content is already
public. Only a pre-commit check prevents the leak.

### Step 1 — PDF (`xu-cheng/latex-action@v3`)

`latexmk -pdf` in `_cv/` on `main.tex` (pdfLaTeX, full TeX Live). Packages used:
titlesec, enumitem, hyperref, array, xcolor, parskip, tabularx, graphicx,
wrapfig, qrcode, comment, geometry, times, setspace, mdframed — all in stock
TeX Live; verified to compile with zero warnings. Output copied to
`files/TianyangChen_CV.pdf`. Comments and `comment` environments are removed by
LaTeX itself.

### Step 2 — HTML fragment (`_cv/tex2html.py`)

Pipeline inside the script (`convert()`):

**2a. Strip shelved content** (`strip_comments`), mirroring what LaTeX does:
- `\begin{comment} … \end{comment}` blocks removed (non-greedy, multi-line).
- `\iffalse … \fi` blocks removed (not nesting-aware).
- On every line, everything from the first `%` not preceded by `\` is removed;
  a line that becomes blank is dropped entirely.
- Each removed block, and each removed `%`-line containing `\item`, `\cventry`
  or `\resumesection`, is reported on stderr as `info: shelved …`. This is
  informational only; shelved content is a supported, long-term practice.

**2b. Extract body**: text between `\begin{document}` and `\end{document}`.
The preamble (including the `\newcommand` definitions) is ignored — the
converter has its own fixed semantics for these macros (table below).

**2c. Split header / sections**: everything before the first `\resumesection`
is the header → `<header class="cv-header">`. The rest is the body.

**2d. Block-level parse** (`blocks`): scans for the block constructs below,
renders them, and treats text in between as paragraphs (blank-line separated,
rendered with `inline`, wrapped in `<p>`).

| LaTeX | HTML |
|---|---|
| `\resumesection{T}` | closes previous `<section>`, opens `<section class="cv-section"><h2>T</h2>` |
| `\cventry{A}{B}{C}{D}{E}` | `<div class="cv-entry">` → `<div class="cv-row"><strong>A</strong><strong>B</strong></div>` → `<div class="cv-row cv-sub"><em>C</em><strong>D</strong></div>` → `E` rendered recursively as blocks |
| `\begin{cvlist} … \end{cvlist}` | `<ul class="cv-list">`; body split on `\item`; each item rendered inline into `<li>`; **empty items are skipped** (warning); text before the first `\item` is an error |
| `\begin{minipage}[pos]{width} … \end{minipage}` | `<div class="cv-minipage">`; a minipage that renders empty (the QR-code one) is omitted |

Environment ends are matched with nesting depth for `cvlist` and `minipage`.

**2e. Inline parse** (`inline`):

| LaTeX | HTML / text |
|---|---|
| `\textbf{x}` | `<strong>x</strong>` |
| `\textit{x}`, `\emph{x}` | `<em>x</em>` |
| `\underline{x}` | `<u>x</u>` |
| `\href{url}{label}` | `<a href="url">label</a>` (url attribute-escaped) |
| `\url{u}` | `<a href="u">u</a>` |
| `{\LARGE x}` (any size command as first token of a group) | `<span class="cv-large">x</span>` (class = `cv-` + lowercased size name) |
| other `{…}` groups | content only |
| `\\` | `<br>` |
| `\\[0.5em]` (positive em/ex/pt/mm/cm/in) | `<br>` plus a block spacer of that height (keeps LaTeX's extra vertical space) |
| `\href{mailto:a@b.c}{…}` and any plain `a@b.c` in text | **not a link**; shown as `a [at] b [dot] c` (anti-scraping; the PDF keeps the real address) |
| `` `` `` / `''` / `'` | “ / ” / ’ |
| `---` / `--` / `~` | — / – / `&nbsp;` |
| `\&` `\%` `\$` `\#` `\_` `\{` `\}` | literal char (`&` escaped) |
| `\textbar{}` `\ldots` `\dots` `\textendash` `\textemdash` `\LaTeX` `\TeX` | `|` `…` `…` `–` `—` `LaTeX` `TeX` |
| `$\sim$`, `$\cdot$`, `$\times$`, `$\pm$`, `$\approx$`, `$\geq$`, `$\leq$` | ∼ · × ± ≈ ≥ ≤ |
| `\vspace`, `\hspace`, `\qrcode` (with optional `[…]` and one `{…}`) | dropped |
| `\hfill`, `\raggedleft`, `\raggedright`, `\centering`, `\noindent`, `\par`, `\newline`, `\smallskip`, `\medskip`, `\bigskip`, bare size commands | dropped |
| raw `<`, `>`, `&` | HTML-escaped |
| **anything else starting with `\`, or other math** | **`ERROR: unsupported command \x` → exit 1** |

Whitespace runs are collapsed to single spaces.

**2f. Output**: the fragment is wrapped as

```
{% raw %}
<div class="cv-tex"> …header… …sections… </div>
{% endraw %}
```

and written to `_includes/cv-body.html`.

### Step 3 — Jekyll (`actions/jekyll-build-pages@v1`)

Builds the repo with the `github-pages` gem set (same as classic Pages).
`_pages/cv.html`:

```liquid
---
layout: archive
title: "CV"
permalink: /cv/
author_profile: true
redirect_from:
  - /resume
---
{% include base_path %}
{% include cv-style.html %}
<p class="cv-download"><a href="{{ base_path }}/files/TianyangChen_CV.pdf">Download PDF</a></p>
{% include cv-body.html %}
```

Liquid runs, the `{% raw %}` wrapper makes Liquid pass the CV markup through
untouched, and because the page is `.html`, kramdown never touches it. The
`archive` layout supplies the site header, sidebar (`author_profile`) and
footer, so the CV is visually part of the site.

### Step 4 — Deploy (`upload-pages-artifact@v3` → `deploy-pages@v4`)

`_site/` is uploaded and deployed. Typical end-to-end time after push: 1–2 min.

### Rendering (`_includes/cv-style.html`)

- Section `h2`: left border in `currentColor` + translucent gray background
  (mirrors the PDF's mdframed headers; works in light and dark themes).
- `.cv-row`: flex, `space-between`; right column (location / dates) right-aligned.
- `≤ 600px` wide: rows stack vertically, right column becomes left-aligned,
  normal weight, 80% opacity.
- No fonts or colors are set; everything is inherited from the theme.

## 4. One-time installation checklist (current repo state as of 2026-10-15)

1. Copy into the repo: `_cv/tex2html.py`, `.githooks/pre-commit` (keep it
   executable), `_includes/cv-style.html`, `_pages/cv.html`,
   `.github/workflows/build-site.yml`, and the owner's `main.tex` as
   `_cv/main.tex`.
2. **Delete `_pages/cv.md`** — it has the same `permalink: /cv/` and would
   conflict. (`_pages/cv-json.md` exists too; it is not in the navigation and
   can be left alone.)
3. Append to `.gitignore`:
   ```
   _includes/cv-body.html
   files/TianyangChen_CV.pdf
   .cv-blocklist
   ```
4. Repo Settings → Pages → Build and deployment → Source: **GitHub Actions**
   (currently "Deploy from a branch"). Without this, the workflow's deploy job
   fails and the old branch build keeps serving the old page.
5. On the owner's machine, once per clone:
   `git config core.hooksPath .githooks`, then create `.cv-blocklist`.
6. Pre-existing workflows, for awareness:
   - `generate_pubs.yml` triggers on branch `master`, which does not exist,
     so it never runs. Unaffected.
   - `scrape_talks.yml` pushes a commit with `GITHUB_TOKEN`. Pushes made with
     `GITHUB_TOKEN` do not trigger other workflows, so after the switch in
     step 4 such a bot commit is deployed only on the next human push or a
     manual run of `build-site.yml`.

## 5. Invariants — do not break these

1. **`_cv/main.tex` is the only content source.** Do not hand-edit
   `_includes/cv-body.html` or the PDF; they are regenerated on every build.
2. **Unknown LaTeX must fail the build.** Never change the converter to skip
   or pass through unknown commands; silent content loss is the failure mode
   this design exists to prevent.
3. **Keep `_pages/cv.html` as `.html`** and keep the `{% raw %}` wrapper.
   As `.md`, kramdown may reinterpret indentation or characters in the CV.
4. **Shelved (commented) content is legitimate** and may stay in the file
   indefinitely. Do not add checks that fail on comments.
5. **The blocklist check stays local** (pre-commit). Do not move it to CI and
   never commit `.cv-blocklist`.
6. **No secrets in this pipeline.** In particular, do not add an Overleaf Git
   token to pull from Overleaf automatically: Overleaf tokens are account-wide
   and would expose the owner's private, unpublished projects.

## 6. Verifying a change

Locally:

```bash
python3 _cv/tex2html.py _cv/main.tex -o _includes/cv-body.html   # expect exit 0; 'info: shelved' lines are normal
latexmk -pdf -cd _cv/main.tex                                     # optional, needs TeX Live
bundle exec jekyll serve                                          # open http://localhost:4000/cv/
```

Checks:
- Every entry in the PDF appears on `/cv/` and nothing else does
  (in particular, nothing that is commented out in `main.tex`).
- Desktop: location/dates right-aligned on the same line as titles.
- Phone width (~390px): rows stack, no horizontal scroll.
- "Download PDF" returns the new PDF (GitHub Pages caches for ~10 min).

In CI: the Actions run is green and its "Convert CV to HTML" step log lists
the expected `info: shelved` lines.

Already verified by the author of this pipeline: PDF compiles cleanly; the
converter renders the current CV completely with shelved content excluded;
unknown macros fail the build; the hook blocks a commit containing a
blocklisted term inside a comment and allows it once removed. **Not yet
verified:** a full Jekyll build of this repo with these files (gem registry
was unreachable in the authoring environment) — check the first Actions run.

## 7. Extending: the owner used a new LaTeX command

Symptom: Actions (or the hook) fails with
`tex2html: ERROR: unsupported command \foo`.

Fix in `_cv/tex2html.py`, choosing the narrowest option:
- Pure formatting/spacing with no content → add to `DROP_NO_ARG`
  (no argument) or `DROP_WITH_ARG` (`\cmd[opt]{arg}`).
- Symbol → add to `SYMBOLS` (one-char command) or `WORD_SYMBOLS`.
- Math symbol → add to `MATH`.
- Inline formatting with content → add an `elif name == "foo":` branch in
  `inline()`, rendering its argument with `inline(p.read_group())`.
- New block macro or environment (new entry type) → add it to `BLOCK_RE` and
  a branch in `blocks()`, plus CSS in `_includes/cv-style.html`.

Then re-run the local verification in §6. Never add a generic fallback.

## 8. Known limitations

- `\iffalse…\fi` blocks cannot be nested.
- `\\%` (line break immediately followed by a comment) is misparsed; write
  `\\ %` instead.
- Only `cvlist` and `minipage` environments are supported; anything else
  (e.g. `itemize`, `tabularx`) fails the build by design.
- The web page has no QR code (it is dropped intentionally).
